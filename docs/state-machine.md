# Order State Machine

## 1. Defined States

The lifecycle of an order consists of 19 discrete states:

```text
CREATED
FILES_UPLOADING
FILES_UPLOADED
CONFIGURATION_PENDING
CONFIGURED
PRICE_CALCULATED
AWAITING_CONFIRMATION
PAYMENT_PENDING
PAID
QUEUED
PRINTING
PRINT_FAILED
MANUAL_REQUIRED
PRINTED
READY_FOR_PICKUP
COLLECTED
EXPIRED
CANCELLED
CLEANUP_PENDING
CLEANED
```

## 2. Legal Transitions

```text
CREATED
  -> FILES_UPLOADING

FILES_UPLOADING
  -> FILES_UPLOADED
  -> EXPIRED

FILES_UPLOADED
  -> CONFIGURATION_PENDING
  -> EXPIRED

CONFIGURATION_PENDING
  -> CONFIGURED
  -> EXPIRED

CONFIGURED
  -> PRICE_CALCULATED

PRICE_CALCULATED
  -> AWAITING_CONFIRMATION

AWAITING_CONFIRMATION
  -> PAYMENT_PENDING
  -> CONFIGURATION_PENDING

PAYMENT_PENDING
  -> PAID
  -> EXPIRED

PAID
  -> QUEUED

QUEUED
  -> PRINTING
  -> CANCELLED

PRINTING
  -> PRINTED
  -> PRINT_FAILED
  -> MANUAL_REQUIRED

PRINT_FAILED
  -> PRINTING
  -> MANUAL_REQUIRED

MANUAL_REQUIRED
  -> PRINTING
  -> PRINTED

PRINTED
  -> READY_FOR_PICKUP

READY_FOR_PICKUP
  -> COLLECTED
  -> EXPIRED

COLLECTED
  -> CLEANUP_PENDING

EXPIRED
  -> CLEANUP_PENDING

CANCELLED
  -> CLEANUP_PENDING

CLEANUP_PENDING
  -> CLEANED
```

## 3. Transition Invariants
- Unpaid orders NEVER transition to `QUEUED` or `PRINTING`.
- Every transition executes inside a database transaction with an `AuditLog` entry.
- Transitions must be strictly verified against the transition matrix.
